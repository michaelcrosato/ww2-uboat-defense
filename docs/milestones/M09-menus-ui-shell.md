# M9 — Menus & UI shell: title, arena setup, dev settings, pause, controls, touch

**Status:** see docs/PLAN.md · **Depends on:** nothing hard (M2 adds the renderer setting it shows) · **Size:** large

## Goal
A DOM UI layer (WWII typewriter/stencil look) fully navigable with mouse, keyboard and gamepad,
plus a secondary touch overlay. Screens are generated from the config schemas wherever possible.

## Read first
`src/core/config.ts` (SettingDef types, presets, `onChange`), `src/core/devSettings.ts`,
`src/game/arenaConfig.ts`, `src/input/input.ts` (actions, `captureHandler`, `glyph`, bindings,
`conflicts`), `src/app.ts`, `src/ui/style.css`, `index.html` (`#ui` root).

## Steps
1. `src/ui/dom.ts`: tiny helpers (`h(tag, props, ...children)`), a screen stack (`push/pop/replace`,
   each screen = `{ el, onEnter, onExit, onBack, update(dt) }`), and **focus navigation**: focusable
   elements get `data-nav`; `menuUp/Down/Left/Right` move focus spatially (nearest element in that
   direction by bounding rect), `menuAccept` clicks, `menuBack` pops; sliders adjust with left/right;
   `menuTabL/R` switch tabs. Mouse hover focuses. UI sounds via `audio.play('ui_*')` if M8 is done
   (guard if not).
2. Widgets: button, toggle, slider (with value label + `fmt`), select (cycle with left/right or a
   dropdown), tabs, tooltip/help text panel, modal confirm. All generated by
   `renderSetting(store, def)`; `showIf` respected.
3. **Title screen** (`src/ui/screens/title.ts`): game title, subtitle, buttons: *Arena* (opens setup),
   *Port* (disabled until M10, label "Port — coming soon"), *Dev Settings*, *Controls*, *Settings*,
   *Credits*. Behind it an **attract mode**: a mission running AI-only (`side` = escort with the
   player ship as AI, or a spectator mode) with a slow orbiting camera — reuse `Mission` with a flag
   `spectator: true` (no player control; camera drifts over the convoy).
4. **Arena setup** (`screens/arenaSetup.ts`): generated from `ARENA_DEFS` grouped by `group`
   (Mission / Environment / Forces), big side picker (Escort vs U-Boat cards with short descriptions),
   *Randomize*, *Reset*, *Launch*. Launch calls `app.startMission({})` (arena store already holds the
   values) and hides the menus.
5. **Dev Settings** (`screens/devSettings.ts`): tabs per group from `dev.groups()`, every setting
   rendered with help text, presets row (`dev.presets`), "reset group", search box (filter by label).
   Live apply (stores notify systems). Settings that need a reload (`display.renderer`) show a
   "reload to apply" note. Accessible from title, pause menu, and a hotkey (`F1`, or Select+Options on
   gamepad) during missions — the mission pauses while open (`app.menuOpen`).
6. **Settings** (player-facing subset): display (fullscreen toggle button using
   `screen.toggleFullscreen()`, pixel size, renderer), audio volumes, controls scheme/deadzone/rumble/
   prompts. Fullscreen also on `F11` / `Alt+Enter`.
7. **Pause menu** (`pause` action): Resume, Dev Settings, Controls, Restart mission, Abandon to title.
8. **Controls / rebinding**: list of `ACTION_LABELS`, two keyboard/mouse slots + one gamepad slot
   per action, capture via `input.captureHandler`, conflicts shown (`input.conflicts()`), reset all;
   glyph preview switches with the active device.
9. **Mission end summary** (temporary until M10): outcome, `mission.result()` numbers (tonnage,
   ships, U-boats, pings, torpedoes), buttons *Again* / *Arena setup* / *Title*. App's
   `MissionHooks.onEnd` opens it.
10. **Touch overlay** (`src/ui/touch.ts`): shown when `controls.touch` = on, or auto + touch device.
    Left half: virtual stick → `input.touchAxes` (steering, direct scheme); right half: drag to aim
    (sets aim point), tap = fire; buttons for abilities 1–6, ping/periscope, charge, depth ±,
    time compression, pause. Uses `input.injectDown/Up` for buttons. Must not affect desktop layout.
11. Boot flow: `main.ts` opens the title instead of starting a mission directly — but URL params that
    set arena values still jump straight into a mission (keep tests working), and `?menu=dev` etc.
    can open a screen directly for screenshots.

## Acceptance
- Screenshots: title (`/?menu=title`), arena setup, dev settings (two different tabs), pause menu over
  a mission, controls screen, touch overlay (`?dev.controls.touch=on`), at 1280×720 and 800×600.
- Keyboard-only navigation works (use `--steps` with arrow keys + Enter to launch a mission from the
  title); a gamepad cannot be simulated headlessly — document the code path instead.
- Changing a dev setting in the menu changes the game live (e.g. `light.bands`).
- 0 page errors; typecheck passes; existing URL-param test flows still start missions directly.
